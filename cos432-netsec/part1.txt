a. What is the DNS hostname of the server it connects to?

ftp.mirror.nl 

b. Is the connection using Active or Passive FTP?

Active FTP, because the client sends a PORT command telling the server what client-side IP address and port to connect back to.

c. Based on the packet capture, what is one major vulnerability of the FTP protocol?

FTP does not encrypt. All communications occur in plain text, which allows attackers to intercept sensitive data. Network administrators monitoring traffic can easily capture FTP sessions too.

4. The trace shows that at least one of the clients makes HTTPS connections to sites other than Facebook. Pick one of these connections and answer the following:

weblogin.umich.edu

b. Is there any way the HTTPS server can protect against the leak of information in (a)? If yes, explain why. If no, explain why not.

c. During the TLS handshake, the client provides a list of supported cipher suites. List the first three cipher suites and name the cryptographic algorithms used in each.

1. TLS_ECDHE_ECDSA_WITH_AES_256_CBC_SHA
Key exchange: ECDHE
Authentication / signature: ECDSA
Encryption: AES-256 in CBC mode
Integrity / hash: SHA-1

2. TLS_ECDHE_RSA_WITH_AES_256_CBC_SHA
Key exchange: ECDHE
Authentication / signature: RSA
Encryption: AES-256 in CBC mode
Integrity / hash: SHA-1

3. TLS_DHE_RSA_WITH_CAMELLIA_256_CBC_SHA
Key exchange: DHE
Authentication / signature: RSA
Encryption: Camellia-256 in CBC mode
Integrity / hash: SHA-1


d. Are any of these three cipher suites worrisome from a security or privacy perspective? Why?

Yes, these cipher suites are worrisome. Although they provide forward secrecy through ECDHE or DHE, they rely on SHA-1 for integrity and CBC-mode encryption. These algorithms are considered outdated and vulnerable to attacks, such as collision attacks on SHA-1 and padding oracle attacks on CBC.

e. What cipher suite does the server choose for the connection?

TLS_DHE_RSA_WITH_AES_256_CBC_SHA

5. One of the clients makes a number of requests to Facebook.

a. Even though logins are processed over HTTPS, what is insecure about the way the browser is authenticated to Facebook?

Even though the Facebook login itself is done over HTTPS, the browser is later authenticated using session cookies that are sent in unencrypted HTTP requests. In the trace, cookies such as c_user and xs are visible in plaintext. c_user leaks the logged-in account, and xs is part of the session or authentication state. 

b. How would this let an attacker impersonate the user on Facebook?

If those cookies are sent over unencrypted HTTP, an attacker can reuse them and hijack their Facebook session without knowing the password.


c. How can users protect themselves against this type of attack?

Users can protect themselves by only using Facebook over HTTPS, so session cookies are never sent in plaintext. They should avoid logging into Facebook on untrusted or open Wi-Fi networks unless the connection is protected, for example with HTTPS-only browsing. Using a VPN also helps prevent cookie theft.

The trace includes "/ajax/messaging/send.php", so the user likely sent a message or attempted to send one. Lastly, the browser loaded Facebook social-plugin content associated with external sites such as Al Jazeera and Errata Security. The plugin traffic however does not show whether the user actively interacted with Facebook content on those pages.
